# Leo for iOS — v1

Status: draft for approval · 2026-10-10

## Goal

A native iPhone/iPad agent manager for Leo. From the phone you can see every
agent across your daemons, get pushed when one needs you, act on it (stop,
restart, interrupt, switch environment), watch its tmux session, open files
agents surface, and hand the conversation itself to the Claude app via Remote
Control.

Ships to Evan via TestFlight first; built so it can go to the App Store later
without redoing pairing, auth, or push.

## Non-goals (v1)

- Typing into the terminal (read-only viewer only; input is v1.1).
- Spawning agents, templates, tasks/cron UI.
- Rendering the conversation natively — that is the Claude app's job.
- Ghostty/libghostty on iOS.
- Relaying terminal or API traffic through a Blackpaw service (push only).
- App Store submission, onboarding polish, iPad-specific features.

## Decisions

| Area | Decision |
|---|---|
| Repo | Same repo. `ios/` app, `Packages/LeoKit` shared package, `relay/` push Worker. Daemon changes land in `blackpaw-studio/leo`. |
| Shared code | `LeoKit` (plain Swift, no TCA, no AppKit) extracted from `macos/Sources/Features/Leo`; the Mac app migrates onto it in the same effort. |
| UI | UIKit + TCA (`observe {}`, swift-navigation UIKit tools). No SwiftUI. Universal app; `UISplitViewController` on iPad. iOS 26 minimum. |
| Terminal | SwiftTerm, fed by a daemon WebSocket. |
| Conversation | Claude app via Remote Control (already on by default in Leo templates). |
| Transport | HTTPS + SSE + WebSocket on one origin per daemon (e.g. `leo.olympus.nyc` via Cloudflare Tunnel, or Tailscale). Plain HTTP allowed only for LAN (`NSAllowsLocalNetworking`). |
| Auth | Per-device bearer tokens issued by QR pairing; optional Cloudflare Access service-token headers per daemon. |
| Push | Stateless Cloudflare Worker relay; payloads end-to-end encrypted; decrypted by a Notification Service Extension. |

## Architecture

```
iPhone ──HTTPS/SSE/WS──▶ leo daemon (web listener)  ──▶ tmux -L leo, agents
   ▲                          │
   └── APNs ◀── push Worker ◀─┘  (ciphertext only)
```

Each machine runs its own daemon; the app holds a list of paired daemons and
merges their agents into one list.

### 1. LeoKit (Swift package)

Moves in: `Models/`, `Daemon/` client protocol + HTTP + envelope,
`Observe/` (SSE parser, observed state, wire types), attention reducer and
types, surfaced-file index/ledger, `LeoFileAccess` protocol + value types.

Cuts required:
- Attention reducer stops taking `LeoAgentRow.ID/Activity` (sidebar types);
  use LeoKit-owned IDs.
- Shell escaper moves out of `Ghostty.Shell` into LeoKit.

Adds: `LeoHTTPSTransport` (URLSession; bearer + optional CF Access headers;
SSE via `bytes(for:)`) beside the Mac's unix-socket transport.

Stays in the Mac app: unix-socket/NW transport, SFTP launcher, Hosts, CLI,
all UI. LeoKit tests run as a SwiftPM test target in CI; Mac tests that move
with the code move to it.

### 2. Daemon additions (leo repo, web listener only)

All routes require a bearer token (existing `api.token` or a device token).

| Route | Behaviour |
|---|---|
| `leo pair` (CLI) | Prints a QR + text code: `{daemon_id, name, urls[], pairing_code}`. `urls` come from new config `web.public_urls` (falls back to LAN addresses). Code is one-time, expires in 5 min. |
| `POST /api/v1/pair` | Body `{pairing_code, device_name}` → `{device_id, token}`. Unauthenticated; rate-limited; code consumed on first use. |
| `leo devices list` / `revoke <id>` | Device tokens stored hashed under the state dir. |
| `PUT /api/v1/devices/{id}/push` | `{grant, key}` from the app (see Push). Replaces any previous registration. |
| `GET /api/v1/agents/{name}/attach` | WebSocket. Daemon runs `tmux -L leo attach -r -t <session>` in a PTY. Binary frames = output; text frames = JSON control (`{"type":"ping"}`). Input frames are rejected in v1. |
| `GET /api/v1/files/{surfaced_id}` | Streams a surfaced file by its surfaced-file **id** (never a path). Supports `Range`, `HEAD`; 404 once evicted from the store. |

Also:
- tmux server option `window-size largest`, so a phone viewer never shrinks the Mac's window.
- Claude harness passes the agent name to Remote Control (`--remote-control "<agent>"`) so sessions are findable by name.
- SSE and WebSocket send a heartbeat every 30 s (Cloudflare idle timeout is ~100 s).
- Push: on each attention transition into a needs-you state (the daemon's existing attention contract), POST to the relay for every registered device.

Existing routes reused as-is: `/api/v1/state`, `/api/v1/events`, `/api/agent/{name}/…` control verbs, environments.

### 3. Push relay (`relay/`, Cloudflare Worker)

- `POST /register {apns_token}` → `{grant}` where grant = token + HMAC(secret).
- `POST /push {grant, ciphertext, collapse_id}` → verifies HMAC, signs the APNs JWT with the Blackpaw `.p8` (Worker secret), sends `mutable-content: 1`, `apns-collapse-id` = agent.
- Rate limit per grant via the Workers rate-limiting binding (30/min).
- No storage. Rotating the HMAC secret revokes all grants.
- Payload: AES-GCM with a per-device 256-bit key generated on the phone and given only to the daemon. Plaintext `{daemon_id, agent, kind, title}`.
- **Step 0:** a throwaway Worker that sends one push to Evan's phone proves HTTP/2-to-APNs from Workers before anything else is built.

### 4. iOS app (`ios/`)

Screens (TCA features):
- **Daemons** — paired list, add via QR scan or paste, connection status, revoke/forget.
- **Agents** — merged live list grouped by daemon; attention badges first.
- **Agent** — state, attention, environment; actions stop/restart/interrupt/switch environment (confirm destructive ones); **Open in Claude**; **Terminal**; **Files**.
- **Terminal** — SwiftTerm, read-only, pinch-zoom + pan at the Mac's width, reconnect on drop.
- **Files** — the agent's surfaced files; QuickLook for images/PDF/video/office; text/code view that jumps to `line`; rendered Markdown; share sheet.
- **Settings** — notifications on/off, per-daemon CF Access credentials.

Notification tap deep-links to the Agent screen.

"Open in Claude": opens the Claude app's Code session list
(`https://claude.ai/code` universal link). Session-specific deep link only if
the spike below finds a supported way to get the session URL.

Secrets (device tokens, CF Access secrets, push keys) live in the Keychain;
the push key is shared with the Notification Service Extension via an app
group keychain.

Connections are foreground-only: SSE and WebSockets close on background and
resume on foreground; push covers the background.

## Testing

- **LeoKit:** Swift Testing, run via SwiftPM in CI.
- **App features:** TCA `TestStore` against an injected fake daemon client and test clock. Tests cover reconnect and backoff, attention ordering, action errors, and pairing failures.
- **Daemon (Go):** pairing (expiry, reuse, rate limit), token hashing and revoke, file route (id-only, Range, eviction 404), attach (read-only enforced, heartbeat).
- **Relay:** vitest + Miniflare. Covers HMAC rejection, rate limit, and the JWT shape.
- **Done for v1** means watching it on a real phone over the Cloudflare Tunnel:
  - pair
  - receive a push while the app is backgrounded
  - tap through to the agent
  - stop it
  - view its terminal
  - open a surfaced PNG and a Markdown file at a line
  - open in Claude

## CI / release

- A path-filtered `leo-ios` job on the self-hosted macOS runner runs LeoKit tests, an iOS simulator build, and the app tests.
- The Mac `leo-ci` job keeps running and builds against LeoKit.
- TestFlight upload runs from a manual workflow. The tag scheme `leo-ios-vX.Y.Z` stays separate from `leo-v*`.

## Build order

1. Push proof of concept (Worker → APNs to Evan's phone).
2. LeoKit extraction, with the Mac app migrated and green.
3. Daemon: pairing and device tokens, files route, attach route, tmux `window-size`, Remote Control session name, heartbeats.
4. iOS app: daemons and pairing → agents → agent actions → terminal → files.
5. Relay hardened, plus daemon push sending and the Notification Service Extension.
6. TestFlight.

## Risks / spikes

- **Workers → APNs over HTTP/2:** unproven. Covered by step 1. If it fails, fall back to a tiny Go relay on Olympus with the same API.
- **Remote Control session URL:** there's no known programmatic source. Spike this. The universal-link fallback is acceptable for v1.
- **Surfaced files are in memory** (20 per agent, lost on daemon restart). This is acceptable for v1; persistence is a daemon follow-up.
- **SwiftTerm performance** on heavy agent output: check this early in step 4.
