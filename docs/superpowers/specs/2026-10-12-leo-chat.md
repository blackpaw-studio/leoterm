# Leo Chat — per-agent messaging in the Leo apps

Status: approved 2026-10-12. Replaces Evan's Telegram channel usage.

## Goal

Message any Leo agent from the Leo iOS and Mac apps — text, voice notes, photos,
files — receive scheduled-task output in the owning agent's thread, reply to it
with run context attached, and answer `ask` questions and Claude permission
prompts inline. Telegram keeps running until migration finishes.

## Decisions

| Topic | Decision |
|---|---|
| Ownership | The leo daemon owns chat state and routing; apps are clients. |
| Thread | One thread per agent, keyed by agent name. |
| Task output | `owner` agent per task; output posts as a task card in the owner's thread. |
| Agent replies | Auto-capture the final assistant message of a chat-initiated turn; tools for everything else. |
| Prompts | `leo_chat_ask` choices and Claude permission prompts answerable in chat, v1. |
| Voice | Local `whisper-cli` (whisper.cpp, `large-v3-turbo`) on the daemon host. No cloud fallback. |
| Attachments | Photos and files inbound in v1. Outbound files reuse surfaced files. |
| Stopped agents | Messaging a stopped agent starts it, then delivers. |
| Migration | Ship v1, then Rocket moves tasks one at a time; Telegram disabled after the last. |

## Daemon (blackpaw-studio/leo — PR, reviewed and merged by the `leo` agent)

### Store
- SQLite at `~/.leo/state/chat.db` (pure-Go driver, WAL). First DB in the daemon.
- `messages`: `id` (ULID), `agent`, `direction` (`in`|`out`), `kind`
  (`text`|`voice`|`file`|`task`|`ask`|`permission`|`system`), `text`,
  `transcript`, `reply_to`, `task` (name), `run_id`, `state` (kind-specific,
  e.g. `pending|delivered|failed`, `open|answered|expired`), `answer`, `ts`.
- `attachments`: `id`, `message_id`, `filename`, `mime`, `bytes`, `path`.
  Files live under `~/.leo/state/chat/attachments/<agent>/<id>/<sanitized name>`.
- Retention: messages kept indefinitely; attachment files pruned after 90 days
  (row kept, `path` cleared).

### API (operator and device tokens)
- `GET /api/v1/chat/threads` — agents with messages: last message, unread count, pinned flag.
- `GET /api/v1/chat/{agent}/messages?before=&limit=&task=` — newest-first page (max 200); `task` filters cards.
- `POST /api/v1/chat/{agent}/messages` — `{text, reply_to?, attachment_ids?}`.
- `POST /api/v1/chat/uploads` — multipart, one file, 50 MB cap; returns attachment id. Audio uploads become `voice`.
- `GET /api/v1/chat/attachments/{id}` — with Range support.
- `POST /api/v1/chat/{agent}/messages/{id}/answer` — `{value}` for `ask` and `permission` messages.
- `POST /api/v1/chat/{agent}/read` — mark read up to an id.
- SSE on `/api/v1/events`: `chat.message`, `chat.updated` (transcript ready, state change, answer).

### Inbound delivery
1. Persist the message (`pending`). For `voice`, run `whisper-cli` (ffmpeg converts to 16 kHz WAV), store the transcript, and emit `chat.updated`. On failure, deliver with a `transcription failed` note.
2. If the agent is stopped, start it and post a `system` message ("Starting…").
3. Deliver through the outbox and bridge as a user turn:
   `[Leo Chat] <text or transcript>`, plus `Attachments: <abs paths>` and, when
   replying to a task card, `In reply to task <name> run <run_id> (<ts>): <card text, ≤1500 chars>`.
4. Mark the agent `awaiting_chat_reply` (stores the message id); mark the message `delivered`.

### Outbound
- **Auto-capture.** On a Stop hook for an agent with `awaiting_chat_reply`, read the
  last assistant message from the hook's transcript and post it, unless the agent
  called `leo_chat_post` since delivery. Clear the flag either way. Empty final message → nothing posted.
- **MCP tools** (Leo MCP server, agent token, own thread only):
  - `leo_chat_post {text, files?}` — `files` are absolute paths; copied into the attachment store.
  - `leo_chat_ask {question, options[≤12], timeout_s=300 (max 3600)}` — blocks; returns `{value, label, timed_out}`.
  - `leo_chat_history {limit≤200, before?, task?}`.
- **Task runs.** The runner exports `LEO_TASK` and `LEO_RUN_ID` to headless runs.
  `leo_chat_post` from a run posts kind `task` into the owner's thread with `task`/`run_id` set.
- **Task owner.** New `TaskConfig.owner`. Default: the agent whose workspace equals
  the task workspace, else `assistant`. Validated at config load (unknown agent → config error).

### Permission prompts
- Install the `PermissionRequest` hook (already used for dispatches) for every
  bridged Claude agent. The hook posts a `permission` message (tool name and
  summarized input) and long-polls the daemon for up to 120 s
  (`chat.permission_timeout`).
- Chat answers: `allow` or `deny` → returned as the hook decision. Timeout → no
  decision, Claude shows its normal terminal prompt, message → `expired`.
- **Verify first:** whether Claude Code's terminal dialog is visible while the hook is pending. If it is, a terminal answer must mark the chat message `answered`, via the existing `PostToolUse` → `working` transition.

### Push
- New kind `chat` (v1 plaintext unchanged: title = agent, body = text excerpt ≤400 runes).
- Sent for every outbound message. The apps suppress the banner (`willPresent`) when that agent's thread is on screen.
- `ask` and `permission` messages carry the message id so notification actions can answer.

## Clients

### LeoKit (shared)
- `LeoChatClient`: threads, page, send, upload (background `URLSession` on iOS), answer, read. Socket transport on Mac, HTTPS on iOS, matching `LeoDaemonClient` flavors.
- Models for messages and attachments, plus decoding of `chat.*` observe events.

### iOS (UIKit + TCA)
- **Chats** list: pinned (assistant first), then recent, then running; "New chat" picker over all agents.
- **Thread**: compositional `UICollectionView`. Task cards are labelled with task name and time and collapse to one line, with a task filter menu. Long replies are collapsed with "Show more". `ask` and `permission` render buttons. Voice shows a player and the transcript. Images show inline; files open in QuickLook.
- **Composer**: text, hold to record (AVAudioRecorder, AAC m4a, 10 min cap), camera, photo library, Files.
- **Notifications**: thread grouped per agent. Categories add a text-input reply action and `ask`/`permission` buttons, answered via the API from the app delegate.

### Mac
- A chat pane for the agent selected in the sidebar, hosted like the existing control bar. Same thread rendering (SwiftUI in `NSHostingView` is fine on Mac), drag-and-drop attachments, mic button.

## Out of scope (v1)
- Outbound TTS voice replies, reactions, editing and deleting messages.
- Auto-capture for Codex agents (they use the tools).
- Group or multi-agent threads.
- Full-text search UI (the `leo_chat_history` tool covers agent-side lookups).

## Testing
- Daemon (Go): store paging and filtering; owner defaulting and validation;
  delivery framing; auto-capture plus dedupe when `leo_chat_post` was used; ask
  and permission long-poll answer, timeout and expiry; upload cap and path
  sanitization; transcription failure path (fake `whisper-cli` via injected
  command runner). One integration test runs real `whisper-cli` on a 2 s clip,
  skipped when the binary is absent.
- LeoKit: client request and response decoding, `chat.*` event decoding (Swift Testing).
- LeoFeatures: chat list ordering, thread paging, send, upload and answer reducers (TCA `TestStore`).
- E2E: isolated daemon (see the isolated-daemon recipe), with a scripted agent replying via a fake Stop hook; verify on device and Mac by screenshot.

## Delivery
1. Daemon PR → `leo` agent review and merge → daemon release.
2. LeoKit + iOS (can start against this contract with a stub client).
3. Mac pane.
4. Migration (Rocket): per task, set `owner`, swap Telegram `reply` for
   `leo_chat_post`, and move `wharf-observation` triggers to task id `<wharf task>`.
   Disable the Telegram plugin after the last task moves.
