Agent-advertised task progress

Design options for tasks agents report via leo_progress / leo progress. Each agent can run several tasks (agent-chosen id): title, determinate or indeterminate, optional status text and ETA. States: running, stale (no update ~15 min), succeeded, failed, cancelled. Finished tasks linger ~10 min; failed ones stay until dismissed. Needs-you always wins the row subtitle.

Behaviour notes
One card per task, keyed by the agent’s task id; later updates edit the same message, so the thread stays quiet (no message per update).
On finish the card is replaced by a compact result row and stops updating; a failure keeps its last output line and an Open terminal / Dismiss action.
Trade-off: per-task cards scale badly past ~3 concurrent tasks (iOS thread above already stacks three). Alternative: one aggregated card per agent, which is calmer but hides per-task detail.

Trade-off / rule: notify on finish only for tasks that ran ≥ 60 s and only when the agent isn’t the focused one; failures always notify. Needs-you notifications keep priority and replace a finish banner for the same agent. Tapping opens the agent (Mac: selects the row; iOS: AgentDetail).
Not mocked: real SF Symbols/vibrancy (approximated with inline SVG), Liquid Glass materials, popover focus behaviour, the cancelled state’s visuals (shown as a dimmed ✕ like failed, no dedicated frame), and light mode.
